# Match the OpenCode adapter to the current CLI fingerprint

The Console gateway serves free-tier chat models only to the official OpenCode
client — "other clients receive HTTP 403, even with an API key" — so the adapter
has to reproduce what `opencode` really sends. Captured 2.1.4 traffic with a
local MITM proxy and corrected the request shape:

- `User-Agent: opencode/latest/2.1.4/cli` (was `opencode/1.19.3`).
- Send the full header set the CLI sends: `x-opencode-client: cli`, a 40-hex
  `x-opencode-project`, `x-opencode-session`, `x-opencode-session-id`,
  `x-session-affinity` and `x-session-id` all carrying the same `ses_…` id, plus
  `b3` / `traceparent` propagation.
- Chat uses the CLI's path `/inference/openai/v1/chat/completions` instead of
  `/inference/v1/chat/completions`. Model discovery keeps `/inference/v1/models`
  through a new optional `resolveModelsUrl` adapter hook, so chat and listing no
  longer have to share one base URL.
- Chat bodies ask for usage on the final chunk (`stream_options.include_usage`),
  map `max_tokens` to `max_completion_tokens`, and inject the client's `read` +
  `shell` tools instead of the invented `bash`.
- The stored API key is used whenever one exists (free models accept it too);
  `public` stays the fallback for keyless installs.
