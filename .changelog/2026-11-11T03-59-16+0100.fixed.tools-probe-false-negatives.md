# Fix sticky tools:false from weak probes

The tools capability probe now mirrors a real OpenAI tools request
(`get_weather`, `tool_choice: "required"`, then `"auto"`) and only stores
`tools: true|false` after a conclusive HTTP 200 with structured tool calls.
Transport and upstream errors no longer overwrite the flag. `/v1/models` also
stops passthrough of an unverified upstream `tools` field, and empty upstream
error bodies on chat proxy get a JSON explanation instead of a blank 502.
